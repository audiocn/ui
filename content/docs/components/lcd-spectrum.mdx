## Installation

```npm
npx shadcn@latest add @audiocn/lcd-spectrum
```

The CLI also adds the [LCD Display](/docs/components/lcd-display) and the [Spectrum](/docs/components/spectrum).

## Usage

```tsx
import { LcdDisplay } from "@/components/ui/lcd-display";
import { LcdSpectrum } from "@/components/ui/lcd-spectrum";
```

```tsx
const analyser = useAudioAnalyser(stream, { bands: 32 });

<LcdDisplay matrix={false}>
  <LcdSpectrum source={analyser.visual} />
</LcdDisplay>;
```

An LCD Spectrum is a [Spectrum](/docs/components/spectrum) with LCD segments in place of the bars. It has the same level axis, frequency axis and grid, and the same ranges and defaults. Set `minHz`, `maxHz`, `minDb` and `maxDb` to match the analyser that produced the bands, so the axes are labelled correctly. The defaults match `useAudioAnalyser`.

Put it in an `LcdDisplay` with `matrix={false}`. The segments are a canvas that draws its own dot grid, so the bezel and the glass come from the display and the segments stay whole.

Each band is one column of segments. The unlit dots sit behind them in the display's dim ink, and the lit segments use its ink. The source feeds the bands as 0..1 values, the same as the Spectrum.

## Anatomy

```tsx
<LcdSpectrum>
  <LcdSpectrumLevelAxis />
  <LcdSpectrumCanvas />
  <LcdSpectrumFrequencyAxis />
</LcdSpectrum>
```

Leave out an axis to hide it. The axes are the Spectrum's, with the labels in the display's dim ink.

## Examples

### Bar and dot

`mode="bar"` lights every segment up to the level. `mode="dot"` lights only the top one, like the LCD Meter's dot mode. The peak caps show in both.

<ComponentPreview name="lcd-spectrum-modes" />

### Peak caps

With `peakHold`, each column keeps a cap at its highest level. The cap sticks there for a short hold, then falls, accelerating, and fades out as it reaches the bar. It is painted before the bars, so a falling cap passes behind the segments and never covers them.

`peakHold` is off by default, as on the Spectrum.

<ComponentPreview name="lcd-spectrum-peaks" />

### Rows

`rows` sets the number of lit segments per column. The default is 24. Fewer rows read as a coarser, more hardware-like screen; more rows read as a finer display.

<ComponentPreview name="lcd-spectrum-rows" />

### Inks

The analyzer draws in its display's ink, so it follows the display's `variant`: the theme's `--primary` by default, or a fixed `amber`, `green`, `cyan` or `red`.

## Theming

The analyzer reads the display's variables, so it follows the display's `variant`, `appearance` and `size`. The axis labels are sized in `em`, so they grow with the display's `size`.

| Variable or attribute     | Meaning                                     |
| ------------------------- | ------------------------------------------- |
| `--lcd-display-lit`       | The lit segments and the peak caps          |
| `--lcd-display-ink-unlit` | The unlit dots behind the columns           |
| `--lcd-display-ink-dim`   | The axis labels                             |
| `--lcd-spectrum-grid`     | The grid lines. Default: the lit ink at 20% |
| `data-lcd-mode`           | On the spectrum: `bar` or `dot`             |

Outside a display the canvas falls back to its `currentColor`. The colours refresh every half second, so a theme switch repaints without a remount.

## Accessibility

The spectrum is `role="img"` with the label "Frequency spectrum". Give it an `aria-label` of your own when the analyzer shows a specific source, such as a track or a bus. The canvas and the axes are hidden from screen readers.

Under `prefers-reduced-motion` the peak caps are hidden and the bars repaint only when the source changes. Peak motion is decorative, so nothing is lost for a reader.
